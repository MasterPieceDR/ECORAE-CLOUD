# ADR-012: Catálogo de modelos por categoría con ventana de edición de 24 horas

**Contexto.** Al registrar un equipo, el modelo se escribía a mano y se perdía sin aviso si no coincidía con el catálogo.
Además, el catálogo se usa como referencia de trazabilidad: si un modelo cambia después de usarse, los registros
anteriores pierden coherencia. Se pide que los catálogos solo puedan modificarse durante un día.

**Decisión.**
- El catálogo de productos es `cat.modelo_equipo` (marca + categoría hoja). Al elegir una categoría, el formulario solo
  ofrece sus modelos; la base rechaza (`EC422`) un modelo de otra categoría o marca. Si el modelo no está, se guarda como
  texto en `trz.dispositivo.modelo_libre`.
- Cada modelo es editable hasta `editable_hasta` = creación + 24 h. La comprobación ocurre en `api.fn_actualizar_modelo`
  con la fila bloqueada (`FOR UPDATE`) y la hora del servidor de base de datos, nunca la del cliente. Cambiar la foto del
  modelo respeta la misma ventana.
- Solo el administrador puede reabrir por 24 h, con un motivo de 5 a 300 caracteres que queda en `cat.modelo_reapertura`
  y en la auditoría.
- Crean y editan el administrador y el coordinador logístico; el resto solo consulta.
- El frontend muestra «Editable · quedan …» o «Bloqueado desde …» en hora de Ecuador, pero quien decide es la base.

**Alternativas.** Validar la ventana en la API (se podría saltar desde otro canal); ventana fijada por fecha por el
administrador (más flexible, pero sin la regla de «un día» automática).

**Consecuencias.** Los modelos semilla quedan bloqueados desde el inicio. Pruebas en `backend/tests/test_fase2.py`:
edición dentro de la ventana, 409 fuera de ella, reapertura por administrador y 403 para el coordinador.
