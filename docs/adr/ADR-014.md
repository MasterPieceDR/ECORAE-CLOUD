# ADR-014: Proyección de recolección con Holt en un módulo aislado

**Contexto.** Se pide un modelo de predicción útil para EcoRAEE que no comprometa la estabilidad del CRUD.

**Decisión.**
- Proyectar equipos (o kg) recibidos por semana y categoría para 4, 8 o 12 semanas con **suavizado exponencial doble de
  Holt** (nivel + tendencia), en Python puro (`backend/app/prediccion.py`).
- α y β se eligen por búsqueda en rejilla (0,1 a 0,9) minimizando el error de las últimas 4 semanas; se informa el
  **MAPE** de esa validación y una banda aproximada del 80 % que crece con el horizonte.
- Historia: 52 semanas sintéticas y reproducibles (`database/18_historial_recoleccion.sql`) más las recepciones reales.
- Endpoint propio `GET /api/v1/prediccion/recoleccion`; ante cualquier error responde `disponible: false` y el resto de
  la API no se entera.

**Alternativas.** Regresión lineal (no se adapta a cambios recientes); ARIMA o Prophet (más precisos con mucha historia,
pero agregan dependencias pesadas y son excesivos para 52 semanas sintéticas); Holt-Winters (requiere al menos dos
ciclos estacionales completos de datos reales).

**Consecuencias.** El modelo sirve para planificar capacidad: la proyección se compara con el flujo máximo de la red.
Limitación: con datos sintéticos el MAPE no mide la realidad; el panel lo advierte.
